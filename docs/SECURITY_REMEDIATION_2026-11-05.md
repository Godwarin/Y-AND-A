# Исправления после независимой проверки Y AND A

Изменения внесены в рабочие исходники. Для семи перепроверенных путей реализованы меры ниже. Уровень доказательств для поведения новой сборки остаётся статическим. BETA-0.42 предшествует этим изменениям и заблокирована для новой подписи и публикации через штатные проверки.

| Путь из аудита | Исправление |
|---|---|
| `airplay/fairplay/msg3-mode-index` | FairPlay отклоняет режим вне 0–3 до сохранения msg3. Вызов C дополнительно сверяет режим, длины 164 и 72 байта и указатели, затем сообщает об ошибке вызывающему коду. |
| `android/main-activity/offer-replacement` | Убран внешний фильтр VIEW. Экспортируемая Activity запускается из меню Android и игнорирует данные внешних Intent. Выбор остаётся за встроенным QR-сканером и ручным вводом. Снимок получателя фиксируется перед системным согласием. Ошибка разбора не выводит исходный код с токеном. |
| `release/standalone-apk-validation-binding` | Перед подписью, при проверке пакета и при проверке готовности сравниваются SHA-256 отдельного, вложенного и ранее проверенного APK. Подпись создаётся по байтам манифеста в памяти. Проверка готовности использует уже проверенный объект манифеста. |
| `airplay/hls/disabled-property-retention` | В режиме без HLS восемь относящихся к нему маршрутов возвращают 404 до вызова обработчиков и записи в реестр. Отдельный режим upstream с включённым HLS не входит в штатную сборку Y AND A. |
| `airplay/setup/udp-handle-ownership` | Legacy SETUP меняет набор сокетов только после успешного выделения всех нужных. Временные сокеты освобождаются при ошибке, старые при успешной замене. Повторный AP2 SETUP использует те же event и timing sockets. |
| `airplay/rtsp/preauth-slot-starvation` | До согласия допускается до четырёх одновременных соединений на адрес и до 45 секунд от подключения. Продление сроков каждого запроса не снимает общий предел. Сохраняется предел 16 общих слотов и 32 допущенных соединений за окно. Заголовки DACP обрабатываются после подтверждения отправителя. |
| `supply/imgui/mutable-git-ref` | Закреплён официальный commit `f401021d5a5d56fe2304056c391e78f81c8d4b8f` и 226 SHA-256 файлов. CMake получает файлы без запуска сборочных определений зависимости и сверяет состав перед компиляцией. Офлайн-кэш проходит ту же сверку. |

Для открытых пунктов также внесены следующие изменения.

- Android учитывает попытку после фильтрации, выделения TLS-состояния и включения её в очередь. Один адрес может занять до четырёх допусков за секундное окно. При невозможности установить TLS 1.3 приёмник завершает запуск.
- AP2 принимает только поддерживаемые типы 96 и 110, максимум по одному в запросе. При повторном создании канала закрываются прежние ресурсы этого типа. Для H.264 добавлены защита от сдвига на 32 бита и нулевая подкладка FFmpeg.
- Для Windows ZIP действует точный список из 583 разрешённых файлов с подстановкой имени вложенного APK. Дополнительные и повторяющиеся записи блокируются. Для планового изменения состава нужен пересмотр `config/windows-package-files.json`.
- При сборе и упаковке исходных зависимостей 11 native архивов сверяются по закреплённым SHA-512, ImGui по SHA-256. Утверждённые значения находятся в репозитории отдельно от локального манифеста упаковки.
- Начальное чтение mirror-соединения ограничено 10 секундами. Граница идентификации двух клиентов с одинаковым видимым IP остаётся открытой. Ограничение времени не создаёт дополнительного криптографического подтверждения медиаканала.

## Результаты проверок

- `cl /Zs` принял все 13 изменённых единиц C/C++, включая Android receiver и границу C FairPlay. Полной линковки и запуска приёмников не было.
- `javac -proc:none --release 17` с локальным SDK, ZXing и существующим сгенерированным R.java скомпилировал Java. В XML отсутствует внешний VIEW, а `MainActivity` не читает URI из Intent.
- PowerShell AST проверен для восьми изменённых и добавленных скриптов. Текущий архив и синтетический корректный комплект прошли проверку связи APK. Пять отрицательных случаев отклонены. Проверены подмена отдельного APK, подмена вложенного APK, лишний файл, выход из разрешённого пути и расхождение хэша ZIP.
- `cmake -P` с `VerifyImGui.cmake` принял 226 файлов официального дерева. Изменённый файл и дополнительный заголовок в фиктивных данных отклонены. Все 11 архивов native совпали с SHA-512 закреплённых portfiles.
- Проверка готовности дала `NOT_READY` для BETA-0.42 по условию `securityRemediationPackaged`. Исходные хэши 100 файлов программы и семи файлов выпуска совпали. Доказательства предыдущих тестов относятся к старому комплекту.

Для проверки новой версии собрать EXE, оба приёмника и APK в новом каталоге. В изолированной среде проверить FairPlay, повторные SETUP, удержание соединений и Android Intent, затем отдельно выполнить обычный сценарий трансляции, звук, поворот, остановку и отказ на поддерживаемых телефонах. Зафиксировать новые хэши и только затем готовить архивы и подпись. Открытые зоны общего аудита перечислены в локальном отчёте `docs/security-independent-2026-11-05/REPORT.md`.
