## Удаление запускателя резервной копии из GitHub, 5 ноября 2026

По просьбе владельца файл «СОХРАНИТЬ КЛЮЧИ.cmd» удалён из текущего main и исключён из ROOT_FILES экспортера, чтобы не возвращаться при следующей подготовке. Личные ключи и резервные копии не затрагиваются. Продуктовый код, EXE и APK не меняются; независимый агент не запускался. Проверка этого этапа: remote tree — файл отсутствует, остальные файлы сохранены. Старые commits не переписываются. Локальные подготовленные архивы соответствуют прежнему snapshot: перед загрузкой Release обновить source ZIP без запускателя и переподписать manifest; текущие assets не загружать как обновлённые.

## Независимый статический аудит, 5 ноября 2026

Выполнены статический анализ, чтение GitHub tree, сверка Git blob SHA для 307 файлов, проверка шаблонов секретов и сверка lock-файлов. Локальный комплект сверили через ECDSA и SHA-256, обе копии APK совпали. Семь записей и 28 единиц охвата прошли экспортируемые validateDocument обоих валидаторов. CLI-режим на Windows недоступен без O_NOFOLLOW и O_NONBLOCK. Продукт, VM и динамические тесты не запускались в этом проходе. Подробности и блокеры в локальном отчёте `docs/security-independent-2026-11-05/REPORT.md`.

## Исправления после независимого аудита, 5 ноября 2026

Статическая проверка 13 единиц C/C++, компиляция Java, разбор 8 скриптов PowerShell, 5 отрицательных проверок APK/ZIP и 2 отрицательные проверки ImGui прошли. Текущая проверка готовности вернула NOT_READY для BETA-0.42. Запуска исправленных приёмников и испытаний новой сборки на устройствах не было. [Команды, объём и ограничения](SECURITY_REMEDIATION_2026-11-05.md).

## Кандидат 0.42a для проверки на телефонах

На 0.42a прошли TypeScript, ESLint, Vitest (3 проверки), Playwright в Edge (8 проверок), `cargo test` и `cargo clippy`. Tauri Release, оба C++ приёмника и APK собраны. Проверены подпись APK v3 и прежний сертификат, SHA-256 563 файлов Windows ZIP, совпадение двух копий APK и целостность 100 файлов замороженной BETA-0.42. [Результаты сборки](evidence/0.42a-local-build.json).

`dumpbin /nologo /dependents` определил 24 прямых DLL-импорта у Y AND A, 20 у Android-приёмника и 34 у AirPlay-приёмника. Все найдены рядом с EXE, в `System32` или представлены контрактами Windows API Set. `aapt2 dump xmltree` подтвердил параметры собранного APK, включая code 401, `targetSdkVersion` 36, отключённые резервное копирование и открытый HTTP, закрытые `ScanActivity` и `StreamService` и единственный фильтр `MAIN` у `MainActivity`. Эти проверки анализируют файлы без запуска приложения.

6 ноября 2026 офлайн-стенд запустился трижды при 5918, 6355 и 6345 МиБ доступной памяти. Образы содержали приёмники с SHA-256 из комплекта 0.42a. Две попытки остановились на пробном AppContainer с кодом `CREATE_LPAC_2`. Диагностика показала доступность EXE и каталога профиля. Создание приостановленного системного `cmd.exe` с тем же токеном тоже вернуло код 2. Снимок восстановлен после каждой попытки. Приёмники не запускались, результат `NEEDS_VALIDATION` для набора из 16 проверок безопасности и 13 проверок протокола Android. Отдельно остаются native smoke 0.42a и проверка телефонов. [Доказательства](evidence/0.42a-isolated-validation.json).

В повторных попытках сбой сохранился при смене рабочего каталога и рабочего стола, после подтверждённой перезагрузки гостя и при общем токене для профиля и процесса. Создание приостановленного пробного процесса вернуло код 2 и до применения прав на папку профиля. В сравнении восьмой попытки обычный ограниченный токен позволил создать системный `cmd.exe`, а AppContainer и LPAC вернули код 2. Приостановленные пробные процессы завершены без продолжения выполнения. Все восемь попыток завершились восстановлением исходного снимка. [Доказательства](evidence/0.42a-isolated-validation.json).

В девятой попытке проверка памяти остановила запуск VM при 5795 МиБ доступных из 5888 МиБ необходимых. Трассировка файловых открытий и открытий ключей реестра подготовлена и пока не выполнялась. `dexdump -d` для извлечённого `classes.dex` подтвердил, что `MainActivity` обрабатывает результат сканирования и не обращается к данным внешнего Intent. В `StreamService` проверены TLS 1.3, сравнение SHA‑256 сертификата с отпечатком из `Pairing` и использование `AudioPlaybackCapture`. APK и приёмники в этой проверке не запускались. [Доказательства](evidence/0.42a-isolated-validation.json), [инструкция проверки на телефонах](DEVICE_TEST_0.42a.md).

6 ноября владелец подтвердил успешную проверку комплекта 0.42a на телефонах, общий статус `OWNER_REPORTED_PASS`. Отдельных результатов по устройствам и сценариям в ответе нет. После подтверждения свободно 4017 МиБ при пороге стенда 5888 МиБ. Новый прогон не запущен. [Отчёт владельца](evidence/0.42a-owner-validation.json).

Для этапа подготовки исходников используются `python -B scripts/prepare-github.py --artifact-version 0.42a` и `python -B scripts/verify-github-source.py --artifact-version 0.42a`. Локальные отчёты находятся в `publish/github-0.42a-manifest.json` и `publish/github-0.42a-security-review.json`. Сканирование шаблонов охватывает известные форматы ключей, токенов и паролей в URL. Статус изолированного прогона остаётся `NEEDS_VALIDATION`.

Верификатор подтвердил состав снимка и локальные ссылки, три изменённых тестовых манифеста отклонил. В старом кэше архива зависимостей 200 файлов ImGui расходятся с текущими закреплёнными SHA-256. Все 226 файлов из закреплённого набора, использованного при сборке, совпадают с текущими пинами. Ещё 300 входов кэша сверены с текущими пинами или lock-файлами. Для полного архива следует обновить входы ImGui и упаковать проверенный снимок 0.42a. На этом этапе VM и приложение не запускались. В GitHub ничего не выгружалось.

В продолжении проверки `collect-source-inputs.py --artifact-version 0.42a` собрал 526 входов без сети, включая 226 проверенных файлов ImGui. Повреждённый синтетический вход с неверным хэшем отклонён до копирования. `verify-package.ps1 -ArtifactVersion 0.42a -SourceOnly` проверил все 844 записи исходного ZIP.

Потоковая проверка ZIP Windows, исходного ZIP и APK прошла. Проверены допустимые пути, CRC, SHA-256 и совпадение отдельного и вложенного APK. Статически просмотрены импорты 57 файлов EXE/DLL. Метаданные закреплённых зависимостей npm и набор пакетов Cargo с их хэшами совпадают с предыдущим снимком. Отчёт находится в `publish/github-0.42a-artifact-metadata.json`.

Повторные прогоны дали файловую и реестровую трассировки. Они подтвердили доступность системного EXE и рабочего каталога, наличие записи AppContainer у тестового пользователя и три обращения с кодом `C0000034` к сопоставлению того же профиля в другой ветке. При 4911 и 5347 МиБ сработала автоматическая остановка из-за памяти. Снимок восстановлен. Приёмники не запускались, 16 проверок безопасности и 13 проверок протокола остаются открытыми. [Доказательства](evidence/0.42a-isolated-validation.json).

После освобождения памяти короткая проверка стартовала при 8257 МиБ и завершила диагностику. Запуск с подстановкой токена пользователя вернул код 5. Проверка после полноценного входа тестовой учётной записи стартовала при 8382 МиБ. Из процесса этой учётной записи удалось создать и завершить приостановленный системный процесс в обычном AppContainer. Создание LPAC из процесса SYSTEM всё ещё возвращало код 2. [Доказательства](evidence/0.42a-isolated-validation.json).

Доверенный процесс в сеансе тестового пользователя создал приостановленный дочерний AppContainer. Проверка признака LPAC через `GetTokenInformation` не подтвердила его и остановила процесс до выполнения. Вариант с проверкой фактического доступа к двум тестовым файлам запустился при 8794 МиБ и достиг входа пользователя. Через 13 минут результат не получен, память во время подготовки оставалась около 4358 МиБ. Снимок восстановлен, запуска приёмников не наблюдалось. [Доказательства](evidence/0.42a-isolated-validation.json).
